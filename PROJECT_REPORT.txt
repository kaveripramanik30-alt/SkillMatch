5. ABSTRACT
================================================================================

SkillMatch is a full-stack freelance platform designed to connect university
students with clients seeking micro-task and project-based freelance services.
Unlike traditional freelance marketplaces that rely on competitive bidding,
SkillMatch uses an intelligent skill-matching algorithm that automatically pairs
clients with the most suitable student based on their registered skill set.

The platform is built using Next.js 16 (App Router) with React 19 on the
frontend, Prisma ORM with SQLite on the backend, and NextAuth.js for secure
credential-based authentication. The UI follows a premium "Superlist-inspired"
dark theme with purple gradients, glassmorphism effects, and micro-animations.

Key features include:
- Role-based dashboards for Students and Clients
- Automated skill-matching engine with percentage-based scoring
- Task lifecycle management (Open -> Pending -> Accepted -> Completed)
- Mock Razorpay payment integration with post-payment rating and review system
- Peer-to-peer task collaboration with dynamic earnings splitting
- Real-time analytics including earnings graphs and activity heatmaps
- Team formation for collaborative project execution (up to 4 members)

The platform serves as a proof-of-concept demonstrating how modern web
technologies can be leveraged to create a streamlined, no-bidding freelance
ecosystem tailored for the student community.

6. INTRODUCTION
================================================================================

6.1 Problem Statement
---------------------
The freelance economy has grown exponentially, yet university students face
significant barriers when trying to participate. Existing platforms like
Fiverr and Upwork are dominated by experienced professionals, making it
nearly impossible for students to compete. The bidding model forces students
to undercut prices, leading to unsustainable earnings. Additionally, these
platforms lack features tailored to the academic ecosystem, such as skill-
based matching aligned with coursework, team collaboration for larger
projects, and micro-task support for quick, small-budget jobs.

There is a clear need for a dedicated platform that:
- Eliminates competitive bidding in favor of intelligent matching
- Provides students a space to monetize their academic skills
- Supports micro-tasks (₹500-₹2000) alongside larger projects
- Enables peer collaboration with transparent earnings splitting

6.2 Overview of the Solution
-----------------------------
SkillMatch addresses these gaps by providing a web-based freelance platform
where clients post tasks with specific skill requirements, and the system
automatically matches them with the best-fit student profiles. The platform
manages the entire task lifecycle from posting to payment, including a
built-in review system that helps students build verifiable portfolios.

6.3 Target Users
-----------------
- Students: University students looking to earn money by applying their
  academic and technical skills to real-world tasks.
- Clients: Individuals or small businesses needing affordable, skill-specific
  freelance work such as bug fixes, presentations, video editing,
  photography, graphic design, and code snippets.

8. TECHNOLOGY STACK
================================================================================

8.1 Frontend
------------
- React 19: The latest version of the React library, used for building
  the component-based user interface with server and client components.

- Next.js 16.2.6 (App Router): A full-stack React framework providing
  server-side rendering (SSR), file-based routing, API routes, and
  Turbopack for fast development builds. The App Router paradigm enables
  React Server Components for optimal performance.

- CSS Modules: Scoped styling using .module.css files for component-level
  encapsulation, preventing style conflicts across the application.

- Vanilla CSS: Custom design system with CSS custom properties (variables)
  for theming, including glassmorphism effects, gradients, and animations.

- Lucide React: A modern, tree-shakeable icon library providing consistent
  SVG icons throughout the interface (e.g., Briefcase, UserCircle, Star).

8.2 Backend
-----------
- Next.js API Routes: Server-side API endpoints built directly within the
  Next.js application under the /api directory. These handle user
  registration, application management, collaboration invites, profile
  updates, and task completion workflows.

- NextAuth.js v4: A flexible authentication library for Next.js supporting
  the Credentials provider. It manages session tokens, role-based access,
  and secure password verification using bcryptjs.

- bcryptjs: A JavaScript implementation of the bcrypt hashing algorithm
  used for securely hashing and comparing user passwords.

8.3 Database
------------
- Prisma ORM v5.20: A type-safe database toolkit that provides an intuitive
  data modeling language (schema.prisma), auto-generated query client, and
  seamless database migrations.

- SQLite: A lightweight, file-based relational database used for development
  and demonstration purposes. The database file (dev.db) is stored locally
  within the project.

8.4 Development Tools
---------------------
- Visual Studio Code: Primary code editor with TypeScript support.
- TypeScript 5: Statically typed superset of JavaScript ensuring type safety
  across the entire codebase.
- Git: Version control system for tracking changes.
- Turbopack: Next.js bundler for fast development builds.
- Prisma Studio: Database GUI for inspecting and managing records.
- ESLint: Code linting tool for enforcing consistent code quality.

9. SYSTEM ARCHITECTURE / DESIGN
================================================================================

9.1 Architecture Overview
--------------------------
SkillMatch follows a monolithic full-stack architecture using the Next.js
App Router pattern. The client and server code coexist within a single
codebase, with clear separation between:

- Server Components: Handle data fetching and rendering on the server
  (e.g., dashboard pages that query the database directly).
- Client Components: Handle interactivity and state management in the
  browser (e.g., modals, forms, buttons marked with "use client").
- API Routes: RESTful endpoints under /api that handle mutations
  (POST, PUT, DELETE operations).

The application uses a Client-Server model where:
- The browser sends HTTP requests to the Next.js server.
- The server processes requests, queries the SQLite database via Prisma,
  and returns rendered HTML or JSON responses.

9.2 Modules of the System
--------------------------

(a) User Authentication Module
    - User registration with role selection (Student/Client)
    - Credential-based login with bcrypt password verification
    - Session management via NextAuth.js
    - Role-based route protection and dashboard rendering

(b) Student Module
    - Profile management (skills, bio, portfolio URL)
    - Skill-matching feed showing compatible open tasks
    - Task application system
    - Active task tracking with collaboration support
    - Earnings analytics (graph + heatmap)
    - Past work history with ratings and reviews

(c) Client Module
    - Task posting with budget, skills, and description
    - Application review with student profiles and match scores
    - Accept/Reject workflow for incoming applications
    - Task completion with mock Razorpay payment
    - Post-payment rating and review submission
    - Spending analytics

(d) Collaboration Module
    - Invite collaborators via email from active tasks
    - Collaboration request inbox for invited students
    - Accept/Reject collaboration invitations
    - Dynamic earnings splitting (even split among all members)
    - Team size enforcement (maximum 4 members)

(e) Matching Engine Module
    - Comma-separated skill parsing and normalization
    - Percentage-based match score calculation
    - Matched vs. missing skill identification
    - Tutorial link generation for skill gaps

(f) Payment Module (Mock)
    - Razorpay-style payment overlay
    - Payment processing animation
    - Post-payment rating modal (1-5 stars)
    - Written review submission
    - Status transition to COMPLETED

9.3 Database Schema (ER Description)
--------------------------------------
The database consists of 6 models:

User (id, name, email, passwordHash, role, createdAt, updatedAt)
  - One-to-One: StudentProfile
  - One-to-Many: Project (as client), Application, TeamMember, Collaboration

StudentProfile (id, userId, skills, portfolioUrl, bio)
  - Belongs to: User

Project (id, clientId, title, description, budget, requiredSkills,
         isMicroTask, status, createdAt, updatedAt)
  - Belongs to: User (client)
  - One-to-Many: Application

Application (id, projectId, studentId, matchScore, status, rating,
             review, createdAt)
  - Belongs to: Project, User (student)
  - One-to-Many: Collaboration

Team (id, name, description, createdAt)
  - One-to-Many: TeamMember

TeamMember (id, teamId, userId, role, joinedAt)
  - Belongs to: Team, User

Collaboration (id, applicationId, studentId, status, createdAt)
  - Belongs to: Application, User (student)

11.2 Frontend Design
---------------------
The frontend is built entirely with React Server Components and Client
Components using the Next.js App Router. Key design decisions:

- Server Components are used for data-heavy pages (dashboards) that query
  the database directly using Prisma, eliminating the need for separate
  API calls and reducing client-side JavaScript.

- Client Components (marked with "use client") handle interactive elements
  like modals, forms, and buttons that require browser-side state.

- CSS Modules provide scoped styling, while globals.css defines the design
  system with CSS custom properties for colors, spacing, and effects.

- The landing page uses a Superlist-inspired layout with a massive centered
  headline, hero images in a CSS Grid layout, and a Bento Box feature grid.

11.3 Backend Logic
-------------------
All backend logic is implemented as Next.js API Routes under /src/app/api/.
Key endpoints:

POST /api/register         - Creates a new user with hashed password
POST /api/projects         - Creates a new task (client only)
POST /api/applications     - Submits a task application (student only)
PUT  /api/applications/[id]/complete - Marks task complete, saves rating
POST /api/collaborations   - Sends collaboration invite
PUT  /api/collaborations/[id] - Accepts/rejects collaboration
PUT  /api/profile          - Updates student profile

Authentication is handled by NextAuth.js with the Credentials provider,
which verifies email/password combinations against bcrypt hashes stored
in the database.

11.4 Skill Matching Algorithm
------------------------------
The matching engine (src/lib/matching.ts) works as follows:

  function calculateMatchScore(studentSkills, requiredSkills):
    1. Parse both skill strings into lowercase arrays
    2. Compare each required skill against the student's skill set
    3. Calculate: score = (matched / total_required) * 100
    4. Return: { score, matchedSkills[], missingSkills[] }

For missing skills, the system generates tutorial links pointing to
relevant learning resources (React docs, Python tutorials, etc.).

11.5 Database Structure
------------------------
The database uses 6 interconnected models managed by Prisma ORM:

- User: Central entity with role-based differentiation
- StudentProfile: Extended profile data for students
- Project: Tasks posted by clients with budget and skill requirements
- Application: Junction between students and projects with status tracking
- Collaboration: Peer-to-peer task collaboration records
- Team/TeamMember: Team formation structure

Key relationships:
- A User (client) has many Projects
- A Project has many Applications
- An Application has many Collaborations
- A User (student) has many Applications and Collaborations

11.6 Key Code Snippets
------------------------

(a) Skill Matching Algorithm:

  export function calculateMatchScore(
    studentSkills: string,
    requiredSkills: string
  ): MatchResult {
    const studentArr = studentSkills.split(',')
      .map(s => s.trim().toLowerCase());
    const requiredArr = requiredSkills.split(',')
      .map(s => s.trim().toLowerCase());

    const matched: string[] = [];
    const missing: string[] = [];

    requiredArr.forEach(reqSkill => {
      if (studentArr.includes(reqSkill)) {
        matched.push(reqSkill);
      } else {
        missing.push(reqSkill);
      }
    });

    const score = Math.round(
      (matched.length / requiredArr.length) * 100
    );
    return { score, matchedSkills: matched, missingSkills: missing };
  }

(b) Dynamic Earnings Split Calculation:

  const totalEarnings = completedTasks.reduce((sum, a) => {
    const activeCollabs = (a.collaborations || [])
      .filter(c => c.status === "ACCEPTED").length;
    const splitCount = activeCollabs + 1;
    return sum + (a.project.budget / splitCount);
  }, 0);

(c) Collaboration API (Invite Endpoint):

  // Verify team size limit

    .filter(c => c.status === "ACCEPTED" || c.status === "PENDING");

  }

15. CHALLENGES FACED
================================================================================

1. Prisma Client Regeneration on Windows
   The Next.js dev server locks the Prisma query engine DLL on Windows,
   preventing schema changes from being applied without a full server
   restart. This required a specific workflow: stop server -> generate ->
   restart.

2. React Server Components vs Client Components
   Balancing server-side data fetching with client-side interactivity
   required careful architectural decisions about which components needed
   the "use client" directive and which could remain as server components.

3. CSS Height Percentage Resolution
   The earnings graph bars initially rendered at 0 height because
   percentage-based heights require an explicitly defined parent height.
   This was a subtle CSS bug that required restructuring the flex layout.

4. State Synchronization Across Dashboards
   Ensuring that when a client accepts a task, the change immediately
   reflects on the student's dashboard required careful data fetching
   patterns and page refresh strategies.

5. Earnings Split Calculation
   Implementing dynamic earnings splitting that correctly accounts for
   varying team sizes across different tasks while maintaining accurate
   totals in the analytics graph required careful mathematical logic.

6. UI/UX Iteration
   Achieving the premium "Superlist" aesthetic required multiple design
   iterations, including adjustments to spacing, gradient intensity,
   typography sizing, and image placement to avoid a cluttered appearance.
